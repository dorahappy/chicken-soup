# 吃饭了 UI 视觉稿说明

版本：v0.2<br>
日期：2026-05-17<br>
状态：待视觉验收

## 1. 交付物

- 视觉稿 HTML：[ui-visual-draft.html](./ui-visual-draft.html)
- 覆盖范围：客户首页、客户下单、客户订单进度、厨师订单看板、厨师采购清单、厨师菜单管理。

打开方式：

```bash
python3 -m http.server 4173
```

然后访问：

```text
http://localhost:4173/docs/ui-visual-draft.html
```

也可以直接在浏览器打开 `docs/ui-visual-draft.html`。

## 2. 视觉方向

v0.2 在 v0.1 的信息架构上调整视觉方向，不走通用后台模板，而是围绕“饭点前协作”和“家庭厨房台面感”设计：

1. 客户侧突出“今天吃什么”“多久能吃”“厨房做到哪了”。
2. 厨师侧突出“新订单”“缺什么材料”“下一步处理动作”。
3. 整体视觉加入浅木纹、暖光和更沉稳的食材色，避免重餐饮 SaaS 的复杂感，也避免外卖平台的强促销感。

## 3. 设计语言

### 3.1 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| 深青蔬绿 | `#2F6F4F` | 主按钮、进行中状态、品牌主色 |
| 熟番茄红 | `#C94B37` | 下单动作、完成提醒、食物记忆点 |
| 木质琥珀 | `#B9781F` | 采购提示、等待状态、轻警示 |
| 备餐蓝灰 | `#3E6584` | 材料数量、辅助标签 |
| 米饭暖白 | `#FFF7E7` | 页面底色和温暖氛围 |
| 木纹浅底 | `#F1DFC6` | 台面感、辅助标签背景 |
| 墨色 | `#20201D` | 主要文字 |

### 3.2 字体与层级

- 字体：系统无衬线字体栈，优先保证中文可读性。
- 移动端首页标题使用 28px 左右，强调饭点入口。
- 卡片标题使用 17-22px，避免在移动端挤压。
- 辅助信息使用 12-14px，并通过色彩和标签控制信息密度。

### 3.3 圆角与卡片

- 主要卡片圆角统一为 8px。
- 移动端手机外框和底部抽屉允许更大圆角，用于表达设备和弹层形态。
- 厨师端页面不堆叠卡片，使用看板、列表和编辑区承载工作流。

## 4. 页面说明

### 4.1 客户首页

目标：让客户 30 秒内完成点单决策。

关键设计：

- 首屏用“今晚可点数量”和预计开饭时间降低决策焦虑。
- 菜品卡片固定展示菜名、描述、制作时长、难度、主要材料。
- 分类筛选使用横向标签，适配移动端单手操作。

### 4.2 客户下单

目标：让客户清楚自己选了什么，并把口味偏好传达给厨师。

关键设计：

- 使用底部抽屉承接下单动作，保留点餐上下文。
- 已选菜品、人数和备注是提交前的核心字段。
- 主按钮使用番茄红，和普通浏览状态拉开层级。

### 4.3 客户订单进度

目标：减少客户反复询问“什么时候吃”。

关键设计：

- 预计开饭时间前置。
- 订单状态使用 5 步流程：已接单、采购确认、备菜中、烹饪中、吃饭啦。
- 采购或延迟信息用琥珀提示块承载，表达“需要注意但不是错误”。

### 4.4 厨师订单看板

目标：让厨师优先处理最新订单和下一步动作。

关键设计：

- 顶部指标展示新订单、待采购材料、预计完成时间。
- 看板按状态分组：新订单、备菜中、烹饪中。
- 每张订单卡保留客户、人数、菜品、备注和主动作按钮。

### 4.5 厨师采购清单

目标：让厨师快速知道本单缺什么。

关键设计：

- 左侧按订单切换，右侧展示材料聚合结果。
- 材料行突出名称、来源菜品和数量。
- 订单备注和“进入备菜”动作固定在右侧，避免采购完成后找不到下一步。

### 4.6 厨师菜单管理

目标：让厨师高效维护今日可点菜单。

关键设计：

- 列表展示菜品分类、时长、难度和材料摘要。
- 今日可点使用开关控件，不需要进入编辑页。
- 右侧编辑区维护菜品基础信息，保存后同步客户菜单。

## 5. 后续开发落地建议

1. 先把现有原型的视觉层替换为本稿的 token、卡片、按钮、状态样式。
2. 客户侧优先做移动端布局，桌面端可居中展示移动版加订单摘要。
3. 厨师侧优先做桌面工作台，移动端保留列表化降级方案。
4. 菜品图片首版可先使用色块/首字占位，后续再接真实图片上传。
5. 状态流和材料清单要独立成组件，便于客户侧和厨师侧复用同一套状态表达。

## 6. 验收点

1. 是否认可当前“家庭厨房 / 小饭桌协作工具”的视觉方向。
2. 客户侧是否足够突出“今天吃什么”和“现在做到哪了”。
3. 厨师侧是否足够突出“新订单”和“缺什么材料”。
4. 是否需要增加桌面端客户页面，或首版只按移动端客户体验开发。
5. 是否需要把真实菜品图片纳入首版开发范围。
